# RuConnect

**RuConnect** — бесплатный open-source сервер управления для [RustDesk](https://github.com/rustdesk/rustdesk).
Работает как Docker-контейнер рядом с официальными открытыми `hbbs`/`hbbr`. Развернуть можно где угодно:
у себя, в облаке или полностью без интернета.

**Клиент RustDesk остаётся штатным, без модификаций.** RuConnect реализует HTTP API, на котором клиент
уже общается с RustDesk Server Pro. Благодаря этому с бесплатными серверами работают функции, которые
обычно платные:

- **учётные записи** в клиенте: вход (с двухфакторной TOTP), личные и общие **адресные книги** с тегами и
  правами по пользователям, вкладка «Доступные устройства»;
- **учёт устройств**: онлайн-статус, ОС/CPU/RAM, владелец, группы устройств, удалённое отключение сессий;
- **аудит**: журнал подключений (кто, откуда, как авторизован, длительность, заметки), передача файлов,
  тревоги безопасности;
- **массовое развёртывание**: `rustdesk --assign` / `rustdesk --deploy` и опции клиента `preset-*`;
- **единый вход**: OIDC-провайдеры (Keycloak, Authentik, Яндекс ID, Google) и LDAP / Active Directory;
- **стратегии**: политики настроек клиента, которые сервер рассылает на устройства (на устройство, группу
  или для всех);
- **группы пользователей** с доступом к группам устройств;
- **мультисерверность**: один RuConnect обслуживает несколько площадок hbbs, и любой клиент подключается
  к устройствам на всех площадках;
- **веб-панель** для всего перечисленного (английский и русский).

## Быстрый старт

Нужны Docker с плагином Compose и открытые для клиентов порты 21114-21119.

```bash
git clone <репозиторий> ruconnect && cd ruconnect/deploy
cp .env.example .env        # укажите в RUCONNECT_ID_SERVER публичный адрес этого сервера
docker compose up -d
docker compose logs ruconnect | grep password   # сгенерированный пароль admin (только при первом запуске)
```

Панель доступна по адресу `http://<хост>:21114`, логин `admin`.

В каждом клиенте RustDesk откройте **Настройки → Сеть → ID/Relay сервер** и заполните поля:

| Поле | Значение |
|---|---|
| ID-сервер | `<хост>` |
| Relay-сервер | `<хост>` (необязательно) |
| API-сервер | `http://<хост>:21114` |
| Key | содержимое `deploy/data/id_ed25519.pub` (его также показывает панель) |

После этого войдите в клиенте под пользователем, созданным в панели.

## Мультисерверность

В клиенте указывается только один ID-сервер. Однако клиент умеет подключаться к устройству через другой
сервер, если его ID записан в формате `ID@хост:порт?key=<ключ>`. RuConnect использует это так:

1. В панели в разделе **Servers** добавьте каждую площадку hbbs: адрес и публичный ключ.
2. Клиенты площадки указывают API-адрес своей площадки: `http://<ruconnect>:21114/s/<slug>`.
   Для площадки по умолчанию адрес остаётся обычным.
3. RuConnect знает, на какой площадке каждое устройство. В адресных книгах и во вкладке «Доступные
   устройства» он выдаёт устройства *других* площадок в виде `ID@хост?key=...`. Пользователь нажимает
   «Подключиться», и клиент сам идёт через нужный сервер.

Устройство одновременно зарегистрировано только на одном hbbs. Подключаться с клиента можно к устройствам
всех площадок.

## Единый вход

**OIDC**: добавьте провайдера в панели (**Провайдеры входа**) и зарегистрируйте у него адрес
перенаправления, который показывает панель (`https://<хост>/api/oidc/callback`). После этого в клиенте
появится кнопка входа через провайдера. Пользователи сопоставляются по подтверждённому email. Если включить
автосоздание, учётная запись создастся при первом входе.

**LDAP / Active Directory**: задайте переменные `RUCONNECT_LDAP_*` (см. `.env.example`). Участники группы
`RUCONNECT_LDAP_ADMIN_GROUP` становятся администраторами, а `RUCONNECT_LDAP_REQUIRED_GROUP` ограничивает
круг тех, кто может войти. Локальная учётная запись с паролем никогда не перехватывается записью каталога
с тем же именем.

## Стратегии

Стратегия — именованный набор опций клиента, например `enable-file-transfer=N` или `approve-mode=click`.
RuConnect рассылает её устройствам через heartbeat. Сначала действует стратегия самого устройства, затем
стратегия его группы, затем стратегия по умолчанию. Пустое значение возвращает опцию к значению по умолчанию.

## Массовое развёртывание

В панели (**Обзор → Настройка клиента**) для каждого сервера генерируется строка конфигурации. Её вставляют
в клиенте в **Настройки → Сеть → ID/Relay сервер → Импорт** или применяют командой
`rustdesk --config <строка>` (от администратора). Чтобы назначить устройства пользователям и группам,
используйте токен развёртывания из **Настроек**:

```bash
rustdesk --assign --token <ТОКЕН> --user_name alice --device_group_name Office
```

Подробнее см. [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

## Настройка

Все параметры задаются переменными окружения, полный список приведён в [README.md](README.md#configuration)
и [`deploy/.env.example`](deploy/.env.example).

**HTTPS.** Поставьте перед портом 21114 обратный прокси (Caddy, nginx, Traefik) и отдавайте API на **443**,
потому что клиент превращает `https://host:21114` в `https://host`. Самоподписанные сертификаты тоже работают.

**Сброс пароля администратора:** `docker compose exec ruconnect ruconnect passwd admin '<новый пароль>'`.

**Резервная копия:** всё состояние хранится в volume `ruconnect-data` (`/data/ruconnect.db`) и в каталоге
`deploy/data` (ключи hbbs).
